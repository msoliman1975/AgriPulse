The inspector is driven by imagery_products.bands and supported_indices, never hard-coded to Sentinel-2. It shows the bands that exist, greys the indices that cannot be computed with the reason, and reports masking as n/a rather than implying a decision was made when none was possible.
No SCL means no cloud masking — so a PlanetScope valid_pixel_pct is not comparable to a Sentinel-2 one. Observer labels the difference instead of letting the two sit in the same column looking alike.

Verify runs

anything wider than one scene
A full verify of one year across 36 blocks is ~2,500 heavy-task executions — not a button that returns a response. Multi-scene verify is a named run with progress, cancel, and a one-run-per-farm guard, exactly like the Backfill Console.

One active run per farm, enforced by a partial unique index — and POST /runs/{id}:cancel from day one. The lesson from #332 is that any run which can hang needs an operator escape hatch that is not “edit the table”.
Verify is the only part of Observer that consumes worker time, so it is the only part that is audited: platform.observer_verify_started / …_completed with tenant, farm, window, mode and scene count. Drill-down views are not audited — a row per pixel click would bury the events that matter.

Radiation is the mean of 9 samples, all between 06:00 and 15:00 — the missing night hours bias the daily mean upward, which inflates ET₀. Coverage is 37.5%, and nothing downstream knows that.
