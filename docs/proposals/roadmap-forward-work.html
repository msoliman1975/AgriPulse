Open decisions answer these before the work starts

Each of these blocks a specific item in the tables. They are questions for Mohamed, not engineering tasks.

T-1 · Is a season a formal thing?

There is no season entity. season_label is free text in two tables that do not reference each other, and four parts of the system pick a season start differently. An Egyptian winter crop already has its growing degree days reset on 1 January, in the middle of the crop.

Blocks: southern-hemisphere season, bearing-year baselines, plan template dates

Q1 · Where does the request language come from?

The design assumes the Accept-Language header with the token claim as fallback. The alternatives are the token claim alone, which does not take effect until the token refreshes, or a database read on every request.

Blocks: P3

Q2 · Portuguese of Portugal or of Brazil?

The code pt covers both and the words differ. If both are needed the registry needs pt-BR and pt-PT, and the resolver needs a region fallback step it does not have. This changes the translation contract, not the code.

Blocks: P8

Q3 · One release per table conversion, or two?

Dropping the old columns in the same migration that adds the new one means the running pods cannot read the table during the rollout. Two releases per table is safe and takes the migration count from 12 to 24.

Blocks: P4

Q4 · Who writes the 841 seed strings?

They are agronomic advice and cannot be machine translated without review by someone who knows the language and the crop. Name the person or the service before P8 starts, because P8 cannot finish without them.

Blocks: Portuguese words

Q5 · Can a platform admin edit Portuguese in the catalogue console?

If yes, the authoring screens in P4 need a language tab per field. That is design work nobody has done.

Blocks: P4 authoring screens

Doing it well needs terrain data we do not have. Doing it badly, on a crop where frost is the catastrophic risk, damages trust. The free frost tree uses forecast air temperature only.
