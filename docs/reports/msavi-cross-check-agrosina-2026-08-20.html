Agrosina MSAVI Cross-Check

A supplied MSAVI GeoTIFF for the Agrosina field is compared against the MSAVI that AgriPulse computes and stores. The formula and the pixel values agree exactly. Every difference on screen comes from the date, the field outline, and the colour legend.

Source files agrosina-1_MSAVI_20Aug2026.tiff (+ ColorMap) Our tenant agrosina Our farm Bashier Elkhier Report written 2026-08-20 21:40 UTC

Result

The AgriPulse MSAVI formula, run on the same Sentinel-2 scene the supplied file uses, reproduces that file to within 0.000000057 across all 7,394 pixels. Correlation is 1.000000. The two systems compute the same number from the same data.

Three pipeline choices, not the maths, move the number that a user sees in AgriPulse: the scene date, the field outline, and the colour legend.

The data file holds 7,394 valid pixels, which is 73.94 hectares. The mean MSAVI over those pixels is 0.15553. The values are continuous floats with no rounding steps, so they were computed from floating-point reflectance, not read back from an 8-bit image.

Part 2

The formula check

I found the Sentinel-2 scene the file must come from. Over this field, one Level-2A scene exists on 20 August:

S2B_MSIL2A_20260820T082559_N0512_R021_T36RVU_20260820T123007, cloud cover 0.06 percent.

I asked Sentinel Hub for bands B04 and B08 of that scene, over the exact bounding box and the exact 80 × 101 grid of the supplied file. I then applied the AgriPulse MSAVI function from backend/app/modules/indices/computation.py:

msavi = (2·NIR + 1 - √((2·NIR + 1)² - 8·(NIR - RED))) / 2

Two follow-up checks rule out a different index or a different band source:

  • SAVI on the same scene differs from the file by 0.0060 on average. NDVI differs by 0.0260. Only MSAVI2 matches.
  • The minimum and maximum agree to six decimal places, -0.011954 and 0.314697, so neither side applied an offset, a gain, or clipping.

I also pulled the MSAVI raster that AgriPulse stored for the 17 August scene out of object storage and recomputed it from its own band file. The stored file and the recomputation agree to 5.7×10-8. The production pipeline computes what the source code says it computes.

Part 3

Where the differences come from

Averaged over the 36 AgriPulse blocks, MSAVI on 17 August is 0.1618. The supplied file averages 0.1555 over its own field outline on 20 August. That gap of 0.0063 breaks down as follows, largest cause first.

Correction, added after this report was first written: AgriPulse does not display a single farm-wide MSAVI number. Every screen shows per-block values. The 0.1618 is a pixel-weighted average across the blocks, computed for this comparison. Part 6 has the detail.

+0.0067on the mean

Cause 1 — The field outline is not the same shape

AgriPulse averages over 36 blocks. The supplied file averages over one field polygon. On the same 20 August scene, the block footprint reads 0.16224 and the supplied footprint reads 0.15553. Nothing about the imagery changed. Only the set of pixels changed.

913 pixels, or 9.1 hectares, lie inside the supplied field but outside every AgriPulse block. Those are the tracks and gaps between blocks, and they read lower than planted ground. 212 pixels, or 2.1 hectares, are the reverse. The AgriPulse farm boundary also runs about 200 m further south than the supplied file's window, so the supplied file does not cover the whole farm we hold.

+0.0004on the mean

Cause 2 — The scene is three days older

AgriPulse holds MSAVI for this farm on 17 August only. The supplied file is 20 August. Held to one fixed footprint, the mean moves from 0.15512 to 0.15553 across those three days. That is small, but the per-pixel change is not. Mean absolute change is 0.0095, the 95th percentile is 0.0277, and the largest is 0.0890. 9.4 percent of pixels cross a class boundary between the two dates.

The 20 August scene was processed at 12:30 UTC. The AgriPulse subscription for this farm last looked for new scenes at 03:23 UTC, about nine hours before the scene existed. The cadence is 24 hours, so the next look is 03:23 UTC on 21 August. The 20 August scene will appear then.

0.0000on the mean

Cause 3 — The legend, which changes the picture but not the number

This is the difference most likely to be noticed on screen, and it involves no disagreement about any value.

The supplied colour map stretches a red-to-green ramp across this field's own range, about -0.01 to 0.31. The field therefore fills the whole ramp, from dark red to green. AgriPulse uses fixed canopy classes at 0.1, 0.2, 0.4, 0.6 and 0.8, the same boundaries it uses for SAVI. On these values that puts 10.8 percent of the field in the lowest class, 72.7 percent in the second, 16.5 percent in the third, and nothing above 0.40.

Both pictures are correct. The supplied one answers "which parts of this field are better than others". The AgriPulse one answers "how much canopy is here", and for bare desert the answer is: very little.

<0.0005on the mean

Cause 4 — Three smaller pipeline effects

Pixel grid. The AgriPulse raster is not on the Sentinel-2 native grid. Its pixels are 10.0217 m by 10.0130 m, with an origin at 464686.47, 3327996.00. The request sends the farm outline's bounding box with a 10 m resolution, and Sentinel Hub adjusts the pixel size to fit that box exactly. Values still match, because Sentinel Hub takes the nearest native pixel instead of blending. On a larger field this can shift a row or column of pixels by one. Fixed on branch fix/imagery-native-grid-and-discovery-anchor: the request now sends a snapped bounding box alongside the outline, which returns exactly 10.000000 m pixels.

Double-counted edges. Each block is rasterised with the touched-pixel rule, so a pixel on the line between two blocks belongs to both. Summing the 36 blocks gives 7,298 pixels where the merged outline gives 6,693. 605 boundary pixels, or 9.0 percent, are counted twice by anything that sums blocks. Part 6 says where that reaches a screen.

Cloud masking. AgriPulse drops cloud, shadow, cirrus and snow pixels using the scene classification band. On 17 August it dropped 35 of 7,485 pixels. On 20 August the scene classification is bare soil across the whole field, so no pixel would be dropped. The supplied file shows no sign of a cloud mask, but on this date it would change nothing.

Part 6

What I suggest changing

  1. Nothing in the index maths. It agrees to float32 precision with an outside source on the same scene.
  2. Put the fetch back on the Sentinel-2 grid. The request now sends a bounding box snapped to whole 10 m steps alongside the field outline, so the output is exactly 10.000000 m per pixel with no resampling. Written, on the same branch. Measured against the live provider on this farm: per-block MSAVI means move by at most 0.0039, once, on the first scene after deploy.
  3. Look for scenes later in the day. A discovery run at 03:23 UTC cannot see a scene that is processed at 12:30 UTC. Written. A daily subscription now also becomes due once the clock passes a configured hour, 14:00 UTC by default. On branch fix/imagery-native-grid-and-discovery-anchor, not merged.
  4. Move the remaining farms to the farm-raster path. I checked the code after writing this report. There is no farm-wide MSAVI number in the product, so nothing displays the double-counted total. The one screen that does add blocks up is the Farm Console legend, and only when a farm has no farm raster. Three of the six farms on production are in that state, so their legend overstates covered ground by about 9 percent. Bashier Elkhier is not one of them; it already reads one histogram over the farm surface. Switching the other three over is a per-farm setting, not a code change, and it also fixes the 9.1 hectares of tracks that no block covers.
  5. Review the MSAVI legend for desert orchards. With the whole field between -0.01 and 0.31, four of the six classes are never used, so the map carries almost no contrast. A second legend that stretches to the field's own range would show the variation the supplied colour map shows.
  6. Backfill MSAVI. This farm has MSAVI on one date only, 17 August, because the index was added forward-only. Every other index on this farm goes back to 17 May.

Method

How to repeat this

  • Read the supplied GeoTIFF with rasterio. Record its bounding box, 464680, 3326990 to 465480, 3328000 in EPSG:32636, and its 80 × 101 grid.
  • From the AgriPulse API pod, query the Sentinel Hub catalogue for that bounding box between 5 and 21 August. Six Level-2A scenes come back. The only 20 August one is S2B_MSIL2A_20260820T082559.
  • Call the Sentinel Hub Process API for B02, B03, B04, B05, B08, B11, B12 and SCL over that exact bounding box at resx = resy = 10, float32 output.
  • Apply the msavi function from backend/app/modules/indices/computation.py and subtract the supplied raster.
  • Read the stored production raster from object storage at sentinel_hub/s2_l2a/S2A_MSIL2A_20260817T082751…/msavi.tif and compare it the same way.
  • Rasterise the farm and block outlines from the tenant database onto the same grid, with the touched-pixel rule, to compare footprints.

This tenant holds three farm records covering the same ground: Bashier Elkhier with 52,129 index rows, B-Elkair-Suez with 7,425, and agrosina-suez with 1,196. Only Bashier Elkhier has imagery jobs. Every comparison here uses Bashier Elkhier.
