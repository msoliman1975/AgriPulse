How a reading becomes advice

A tree reads a cell's numbers, writes down what it finds, and turns the whole list into one card. This is how that works, in plain words.

Part 1

What a run is

A tree runs once for every cell. It answers once, at the end, when it has seen everything.

A cell is the small square of a block that one reading covers. A block is made of hundreds of them. A tree runs against each cell on its own, because a cell at the end of a failing irrigation line is in a different state from the cell beside it.

As the tree runs it asks questions about that cell's numbers and follows the branches. Every time it finds something, it writes it down and carries on. At the end it has a list — empty, or with four things on it — and that list becomes one card.

01 Walk

The tree reads this cell's numbers and follows the branches.

02 Write it down

Each thing it finds is recorded as a short code, with how serious it is.

03 End

Every route finishes at one end point. The list is complete.

04 Fold

The list becomes one card: one sentence, one health class, one action.

The reason the answer waits until the end is that one event moves several readings at once. When an irrigation valve fails, the leaves hold less water, the canopy thins and the plants run warmer. A tree that decided at the first failed check would report the first symptom it happened to meet. A tree that waits can say which cause fits all of them.

One run, one card

However many things a tree finds in a cell, the farmer gets one card about that cell. That is the rule the whole design is built on.

Part 2

The five kinds of step

A tree is steps joined by arrows. There are five kinds and no more.

condition Check

Asks one question about a number. Two ways out: it matched, or it did not.

register Write it down

Records one finding and carries on. This is the step that puts something on the list.

set Remember a value

Keeps a number or a word for later in the same run, so a check is written once instead of four times.

switch Bands

One value, several bands in order. The first band that fits wins, and there is always a fallback.

stop End

The run ends here and the list is folded. Drawn as a circle, because it is not a step the tree takes.

A check can ask more than one thing at a time: every one of these, or any one of these, and the answer can be inverted. A check compares a reading against a fixed number, against a band for this tree size, or against another reading.

Almost every route through a tree ends at the same stop. That is expected. One run, one ending, one card.

Part 3

Findings, and the words on the card

A finding is a code. The words the farmer reads live in one shared list, written once.

When a tree writes down dry, it is not writing a sentence. It is naming something it found. The sentence lives in the finding catalogue, which every tree shares.

The clause is a fragment, not a sentence. It starts in lower case, it ends without a full stop, and it must not contain a comma — the card joins several clauses with commas, so a clause carrying its own comma makes the result unreadable. One code, one wording, everywhere: change it once and every card that names that finding changes with it.

The platform keeps a catalogue every tenant can use, and a tenant can add codes of its own. Where a code exists in both, the platform's wording is the one that is read.

Two different words for "how bad"

Severity

infowarningcritical

Set on the step that writes the finding. It sorts the clauses on the card and decides which action is named first.

It sits on the step rather than on the catalogue, so the same finding can be a warning on a small tree and critical on a large one.

Health class

navery_goodgoodissuealert

Set on the catalogue row, or by a rule. It is what colours the block on the map.

A card takes the worst health class among its findings.

Part 4

How the list becomes a card

The run has finished and the tree holds a list of findings. Two things can happen.

a rule matched vigour_low + dry alert irrigate

Canopy vigour and the water readings dropped together. Water shortage is the cause. Irrigate before treating anything else.

هبطت حيوية المجموع وقراءات الماء معًا. السبب نقص ماء. اروِ القطعة قبل أي معالجة أخرى.

A rule is a sentence the author writes for one exact set of findings. It is where a cause gets named, because a pair often means something neither one means alone.

no rule, so the card writes itself pest_high + dry + vigour_low alert spray

Anthracnose pressure is high, two of the three water readings say this cell is dry, and canopy vigour is below the band for this tree size. Start with the spray.

The clauses are sorted with the most serious first and joined into one sentence. The closing line names what to do first, taken from the most serious finding.

A rule matches a set exactly. A third finding means the rule does not fire, and that is deliberate: three findings are a different situation from two, and the card that writes itself will say all three.

This is why a handful of rules covers thousands of situations. An author writes a rule only where a combination means something special. Everything else still produces a card a person can act on.

An empty list is an answer

A cell where nothing was found opens no card. The tree ran, every check was made, and none of them fired. That is not the same as a cell nobody looked at.

Part 5

The designer

Three tabs. The canvas is where the tree is drawn; the other two are how you know what it will say.

TabWhat it is for
Canvas The tree as a picture. Click a step to edit it, drag a step to move it. Each step shows its kind, its label and the important part of its contents, so bands and findings can be read without opening anything. A + under an empty arrow adds the next step there.
Combinations Every set of findings this tree is able to produce, beside the rules the author has written. A set with a rule is marked as such; a set without one writes its own card. This is the tab that answers "what will a farmer actually read".
Dry run Pick one block and fold every cell in it. The table shows, per cell, what was found, whether a rule matched, and the exact card text.

A position you drag a step to is saved with the tree, so everyone who opens it sees the same arrangement. One button hands the whole picture back to the automatic layout.

A dry run writes nothing. No card is opened, no verdict stored, nothing reaches a farmer. Run it as often as you like. There is a wider version that folds a whole tenant's estate and writes only its own report.

The checks beside the canvas

The panel next to the tree lists what is wrong while you work: an arrow pointing at nothing, a band with no fallback, a finding the catalogue does not know, a route that never reaches the end. Each error lands on the step that caused it, and publishing is held until they are gone.

Part 6

Drafts, publishing, and what runs

Saving, publishing and running are three separate things.

ActionWhat it doesWhy it exists
Save draft Stores a new version on top of the published one Work in progress that anyone opening the tree will see
Publish Fixes one version as the tree's current one The version a run uses, and the one a reviewer reads
Discard draft Deletes the unpublished draft Saving cannot undo, so a draft you do not want has to be removed

Saving a draft that is identical to the last one stores nothing. That is why a draft you regret is discarded rather than saved over.

Publishing is not switching on

Every tree in this designer is marked beta, and the nightly job only picks up trees marked live. Publishing fixes a version that you, the dry run and a reviewer can all point at. It puts nothing in front of a farmer.

Platform trees and tenant trees

A tree belongs either to the platform, where every tenant can see it, or to one tenant, where only they can. A tenant can open a platform tree and dry run it against their own blocks. They cannot change it: the designer shows it read-only and offers no Save.

Part 7

Mango, in practice

The mango content exists in two shapes, and both are in the platform catalogue.

One tree, mango_unified, holds the whole diagnosis: 74 steps, 14 findings, 11 rules. It reads vegetation indices, leaf water, soil moisture, canopy temperature, red-edge, bare ground and three live weather risk scores, and folds all of it into one card per cell.

The same content is also published as four trees named after the work they do.

TreeThe question it answersStepsFindings
mango_water_statusIs this cell short of water? Two of three readings must agree.352
mango_canopy_healthIs the canopy weak, and is the cause feed?335
mango_pest_pressureHow hard is the weather pushing anthracnose, mildew and fruit fly?136
mango_record_checkIs the tree size recorded, so the other three can judge anything?31

Four trees are easier to name, own and change. They cost something, and the cost is worth knowing before choosing: a rule matches the findings of one run, and each tree runs on its own. A rule that pairs a canopy finding with a water finding cannot fire once those two live in different trees. The farmer gets two cards — one saying irrigate, one saying vigour is below the band — and nothing joins them.

A dry run of each shape over the same estate is how that choice gets made.

Part 8

Words used here

Cell
The smallest piece of a block that a reading covers. A tree usually runs once per cell.
Block
A named part of a farm. A block is made of cells.
Run
One tree going through one cell, from the first step to the end.
Finding
One thing a run found, named by a short code. Not a sentence and not a card.
Finding catalogue
The shared list of codes and their wording in both languages.
Fold
Turning the findings of one run into one card.
Rule
A sentence the author writes for one exact set of findings.
Card
What the farmer reads: one sentence, one health class, one action.
Band
The range a reading is expected to sit in for this tree size.
Dry run
Folding a block without writing anything, to see what a tree would say.
Beta
A mark on the tree. The nightly job runs only trees marked live.
Parameter
A named number in the tree, such as a floor or a ceiling, that a tenant can tune without editing steps.
