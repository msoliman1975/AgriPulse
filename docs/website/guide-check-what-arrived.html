Guide · Process 03

Check what arrived

Subscribing starts a queue, not a picture. This is how you tell the difference between data that has not arrived yet and data that is not coming.

Who does this

Tenant admin, platform admin

How long it takes

5 minutes, then whenever something looks wrong

Steps

5 steps

Before you start

  • A farm with at least one subscription. See Turn on imagery and weather.
  • Patience. The first sync waits for the next scheduled run.

Step by step

Check what arrived

Open integration health

  • Go to Settings → Integrations → Health. It shows when weather and imagery last synced for each farm and block, and refreshes every 30 seconds.
  • Six views: Overview, Runs, Queue, Providers, Farms and Blocks.
  • Start on Overview. One row per farm, with a weather column and an imagery column.

Read the states honestly

  • No active subscription means nothing is turned on. Go back and turn it on.
  • Never synced, overdue immediately after subscribing is normal. The job has not run yet.
  • Failing next to Never synced on a farm you have just subscribed is the same thing said harshly. Give it a scheduled cycle before you treat it as a fault.
  • Failing on a farm that used to sync is a real problem. Open Runs to see what the last attempt did.
Note

The way to tell them apart is the Runs view. On the farm we set up for these guides, Overview read Failing, Never synced, 1 overdue while Runs read "No recent ingestion attempts in the last 14 days". Nothing had failed. Nothing had run yet.

Read it per farm, not per block

  • A farm fetched as one area has no per-block jobs at all.
  • So a block-level view of a farm-level subscription looks dead even when everything is working.
  • Use the Farms view for a farm-level subscription, and Blocks only for farms that still fetch per block.

Look at the passes themselves

  • Open the farm in Farm management and read the scene strip: one mark per pass day.
  • Open a pass and check its coverage and cloud figure.
  • A gap in the strip is either cloud, a missed acquisition, or a cloud limit set too low.

Backfill the history, if you need it

  • A new subscription starts from today. Baselines need history, and without a baseline an anomaly cannot be called.
  • Backfill is run by whoever operates the platform, from Platform → Backfill, not from tenant settings.
  • Several years takes hours. Aggregates can lag the raw data, so give the summary tables time before you judge the result.
Note

Ask for a backfill deliberately. It re-reads imagery for every pass in the range, so it is the most expensive thing in this process.

Check it worked
  • The health page shows a weather and an imagery row for the farm.
  • The scene strip shows marks on the dates you expect.
  • The index chart draws a line instead of an empty panel.

Reference

Every field on the form

ViewWhat it answers
OverviewIs each farm syncing, for weather and for imagery.
RunsWhat the recent attempts did, and why one failed.
QueueWhat is waiting to run right now.
ProvidersWhether the upstream provider is answering at all.
FarmsFarm-level detail. The right view for a farm fetched as one area.
BlocksBlock-level detail. Only meaningful for farms that fetch per block.

When it does not work

What you seeWhat it means
Failing, never synced, right after subscribingThe first job has not run. Wait for a scheduled cycle.
Aggregates look fine but jobs look deadYou are reading block jobs on a farm-level subscription. Read the Farms view.
No passes in the scene stripEither no acquisition, or the cloud limit rejected them all.
Numbers on the chart but no baseline bandThere is not enough history. Ask for a backfill.
Backfill finished but the map is unchangedThe summary tables lag the raw data. Give them time before re-running anything.
